# `pop3` decoded data

Transport: TCP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `status`, `username`, `password`, `digest`, `server_name`, `payload`, `truncated`

POP3, plaintext on tcp/110 (plain rule: the greeting goes out on connect, and `STLS` is offered) or POP3S on tcp/995 (rule `tls: true`, so TLS details are in the event's `tls` field, not in frames). The greeting `+OK Dovecot (Ubuntu) ready.` is the first `write` frame (`status` `+OK`), so `payload` is the honeypot's banner; the catch-all's port 110 banner uses the same string. `CAPA` lists `TOP`, `STLS` (only before TLS), `USER`, `UIDL`, `RESP-CODES` and `PIPELINING`. On tcp/110 the handler terminates TLS itself in two cases: after `STLS` (`+OK Begin TLS negotiation now.`, no second greeting; `STLS` once TLS is active gets `-ERR TLS is already active.`), and when the client sends a TLS handshake record instead of a command (implicit TLS on the plaintext port), after which it sends the greeting again over TLS. Either way the client's handshake is a `read` frame with `command` `tls`, `server_name` (SNI) and the raw ClientHello as `payload` (`truncated` if it hit the capture cap), the event gets a `tls` object (with JA3/JA4) and `tls` in its handler stack, and the frames after it are decrypted. A failed handshake ends the session; the `tls` frame still holds the bytes the client sent. A client that sends a ClientHello on 110 has usually already received the plaintext greeting and aborts the handshake, so expect that frame and little else. Reads set `command` to the upper-cased verb (left empty when the line starts with non-printable bytes); `USER` also sets `username`, `PASS` sets `password`, and `APOP` sets `username` and `digest`. `PASS`, `APOP` and `AUTH` always fail. A POP3S scanner that sends no ClientHello, or a non-TLS client, produces an event with empty `decoded` (`null`) and the raw bytes as `payload`. Sessions are capped at 32 commands and 4 KiB lines (`truncated`).
