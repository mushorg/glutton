# `socks` decoded data

Transport: TCP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `path`, `status`, `version`, `host`, `port`, `user`, `password`, `methods`, `payload`, `payload_hash`, `truncated`, plus TLS ClientHello fingerprint fields (`sni`, `ja4`, …) on `tls-clienthello` reads and `error` on a failed `tls-handshake` write

SOCKS4, SOCKS4a and SOCKS5 (tcp/1080, 4145, and any port via the catch-all peek). Read `command` is `socks4-connect`, `socks4a-connect`, `socks4-bind`, `socks5-greeting` (`methods`), `socks5-auth` (`user` and `password`), `socks5-connect`, `socks5-udp-associate`, `tls-clienthello` (tunneled TLS hello after a granted CONNECT), or `tunnel` (plaintext bytes through the tunnel, or the HTTP request after the handshake). `path` is the requested `host:port`. Writes repeat the `command` and set `status` `granted`, `rejected`, `no-auth`, `user-pass`, `no-acceptable-method`, `tls-handshake`, or `200` (canned HTTP judge reply). A SOCKS4a request that stops after the userid (some checkers send the hostname in a later segment, or never; Ochi event b53eecbe-20f7-4fdc-84ea-0a530f6f9833) is granted after one second with an empty `host`, `path` `:port` and `truncated` set on the read frame.

CONNECT is always granted with BND.ADDR `0.0.0.0` (never the sensor address) and a high BND.PORT. Nothing is dialed or forwarded. After the grant, a complete TLS ClientHello in the tunnel is terminated with the shared self-signed `CN=localhost` certificate (event `tls` object set); a following HTTP request, or a plaintext HTTP request in the tunnel, gets a fixed JSON body reporting documentation IP `198.51.100.10` so open-proxy judges (httpbin `/ip`, `api.ipinfo.io`, …) complete their check. Non-HTTP tunnel bytes are stored and the session closes.
