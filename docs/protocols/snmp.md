# `snmp` decoded data

Transport: UDP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `version`, `community`, `request_id`, `non_repeaters`, `max_repetitions`, `oids`, `msg_id`, `msg_flags`, `security_name`, `engine_id`, `context_name`, `status`, `payload`, `truncated`

SNMPv1/v2c/v3 (RFC 3416, RFC 3412) on udp/161. The `read` frame has `version` (`v1`, `v2c`, `v3`), `community` (plaintext, as sent), `command` (the PDU: `GetRequest`, `GetNextRequest`, `GetBulkRequest`, `SetRequest`, `InformRequest`, `SNMPv2-Trap`, ...), `request_id` (the signed INTEGER from the wire), `oids` (dotted, up to 64) and, for GetBulk, `non_repeaters` and `max_repetitions`. A datagram that does not parse is recorded with `command` `unknown` and no reply. For SNMPv3 (`version` `v3`) the header and USM parameters are decoded as far as the datagram is well formed, and the unencrypted scoped PDU supplies `command`, `request_id` and `oids`: `msg_id`, `msg_flags` (1 auth, 2 priv, 4 reportable), `security_name` (the USM user, plaintext as sent), `engine_id` (the client's authoritativeEngineID in hex; empty is discovery) and `context_name`. A truncated or malformed v3 body keeps the fields decoded before the break, with `command` `unknown` if the PDU was not reached.

The honeypot is a read-only embedded Linux router. The persona (kernel, build date, architecture, host name `gw-xxxx`, boot time) is derived per process, and `sysUpTime` advances. It answers community `public` only, for the system group `1.3.6.1.2.1.1` (`sysDescr`, `sysObjectID`, `sysUpTime`, `sysContact`, `sysName`, `sysLocation`):

- GET: values, `noSuchObject` for unknown OIDs (v2c) or `noSuchName` (v1, `status` `no_such_name`).
- GETNEXT / GETBULK: walk the system group and end with `endOfMibView`. Repetitions are capped at 64.
- SET: `noAccess` (v2c, `status` `no_access`) or `noSuchName` (v1). Nothing is ever written.
- SNMPv3 USM discovery: a reportable, noAuthNoPriv message gets a `Report` PDU (`write` frame `command` `Report`). With an engineID other than the agent's (including the empty discovery one) the Report carries `usmStatsUnknownEngineIDs.0` and the agent's authoritativeEngineID, boots and time (`status` `unknown_engine_id`). With the agent's own engineID, as a scanner sends after learning it, the Report carries `usmStatsUnknownUserNames.0` (`status` `unknown_user_name`), because the agent has no users. The engineID is RFC 3411 format (enterprise 8072, format 0x80, 8 bytes derived per process), so it differs between sensors; the counters start at per-process values and advance on every Report. Authentication and privacy are not implemented.
- Any other community, authenticated, encrypted or non-reportable SNMPv3 messages, other security models, GetBulk over v1 and non-request PDUs get no reply, as a real agent drops them. They are still recorded.

v1/v2c replies are never larger than the request (reflection abuse resistance). A v3 Report is the exception: it is about 105 bytes, larger than a minimal discovery probe, and is capped at 160 bytes (an amplification factor under 3, bounded by `udp_reply_limit`) so discovery is not silenced. A GetBulk reply drops trailing bindings until it fits; a Get/GetNext/Set reply that does not fit becomes a `tooBig` error (`status` `too_big`, empty bindings), and if even that does not fit nothing is sent. Most minimal probes therefore see `tooBig`. The `write` frame has `command` `GetResponse` and `status` `ok`, `too_big`, `no_such_name` or `no_access`. Replies go to the datagram source and count toward `udp_reply_limit`.

Probes seen: a v3 discovery GetRequest for `sysObjectID.0` with empty engineID and user (Ochi event da656960-b52d-4f05-a47f-da632ad36e57), the stock engine-discovery probe of SNMP scanners (a guess); a v2c GetBulk of `1.3.6.1` with `max-repetitions` 2000 and community `public` (Ochi event 7046da12-95f6-463e-8b55-8df479078229), the shape of an SNMP discovery and amplification check (a guess).

Generic `udp` reroutes well-formed SNMP on any port: an outer SEQUENCE spanning the datagram, version 0, 1 or 3, and for v1/v2c a community followed by a PDU tag 0xA0-0xA7 (v3: the msgGlobalData SEQUENCE). `udp dst port 161` maps to `snmp` before the catch-all.
