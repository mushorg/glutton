# `ike` decoded data

Transport: UDP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `status`, `version`, `spi_i`, `spi_r` (hex), `encryption`, `prf`, `integrity`, `dh_groups`, `hash`, `auth_method`, `life`, `ke_group`, `identity`, `id_type`, `nonce_len`, `notifies`, `vendor_ids` (hex), `nat_t`, `prefix` (hex), `payload`, `truncated`

udp/500 and udp/4500 (`nat_t` when the non-ESP marker is present; replies keep it). `command` is the exchange name. Reads list every offered transform name (key length suffixed, e.g. `AES_CBC_256`). IKEv1 Main Mode reads also set `hash`, `auth_method`, `life` (seconds) and `dh_groups` from each transform's attribute set. An Aggressive Mode read sets `id_type`, `identity`, `nonce_len` and `ke_group` and gets no reply. IKEv2 IKE_SA_INIT requests get a stateless reply: `INVALID_KE_PAYLOAD` asking for MODP_2048/ECP_256/ECP_384 when the KE group differs, a full IKE_SA_INIT (chosen transforms, random KE and nonce) when it matches, or `NO_PROPOSAL_CHOSEN`. IKEv1 Main Mode (exchange `IDENTITY_PROTECTION`, zero responder SPI) gets message 2: the chosen transform (AES-256/SHA2-256/MODP_2048/PSK first, down to AES-128/SHA1/MODP_1024/PSK) and the Vendor IDs of a common gateway (RFC 3947 NAT-T, draft-ietf-ipsec-nat-t-ike-02, DPD, XAUTH). The write frame's `command` and `status` are `IDENTITY_PROTECTION`, or `status` `NO_PROPOSAL_CHOSEN` when nothing matches. A reply larger than twice the request is not sent. Datagrams over 4096 bytes are capped with `truncated`. An IKE message behind up to 32 other bytes (not the non-ESP marker) is decoded from its real header, the skipped bytes are recorded in `prefix`, and no reply is sent (a gateway would drop it as ESP). A datagram of 28 bytes or more with no plausible IKE header gets `command` `malformed` and no header fields; `payload` keeps the raw bytes.
