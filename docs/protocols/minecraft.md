# `minecraft` decoded data

Transport: TCP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `path`, `status`, `protocol_version`, `port`, `next_state`, `username`, `variant`, `visit`, `truncated`, `payload`

Minecraft Java. `command` is `handshake` (`path` is the server address the client typed), `status_request`, `ping`, `login_start` (`username`), `malformed` (partial or oversize frame, `truncated`) or `unknown`. Writes set `status` `status_response`, `pong`, or the login Disconnect reason: `incompatible` / `outdated_client` (login Handshake protocol is not 769; below 754 is `outdated_client`), `transfers_disabled` (next state 3), or `not_whitelisted` (Login Start with protocol 769).

Replies mimic a vanilla 1.21.4 dedicated server in offline mode with a whitelist. The status JSON always advertises version `{"name":"1.21.4","protocol":769}` whatever protocol the client sends; its MOTD and players come from a persona picked per source visit (see `recall.enabled` in [configuration](../configuration.md)). A first visit gets `default`, `{"description":"A Minecraft Server","players":{"max":20,"online":0},"version":{"name":"1.21.4","protocol":769}}`; a source returning after `recall.visit_gap` gets the next of `smp` (`Friends SMP`, 2 of 10 online) and `survival` (`survival server - whitelist only`, 1 of 20 online), whose `players.sample` lists the online names with their offline-mode UUIDs. The `status_response` write carries `variant` (the persona) and `visit` (the source's visit number). Disconnects carry translatable components (`{"translate":"multiplayer.disconnect.…"}`). Version and transfer rejections are sent right after the Handshake, as vanilla does, so they come before any Login Start. The handler then waits up to 500 ms for a Login Start already in flight and records it (`username`) without answering. A second Status Request closes the session. No encryption or real login.

The rule routes tcp/25565 here. On any other port the `tcp` catch-all peeks the first segment and reroutes a complete Handshake (length prefix 6–266, packet ID `0x00`, address of 255 bytes or less, next state 1–3, fields ending at the declared length) to this handler, so server-list scanners on high ports (e.g. matscan) show up as `minecraft`.

**Legacy ping.** A pre-1.7 server list ping (`FE 01`, optionally followed by the `FA MC|PingHost` plugin message; nmap sends it) is read as one frame with `command` `legacy_ping` and answered with a 1.4+ kick packet (`0xFF`, UTF-16BE `§1`, protocol 127, version `1.21.4`, the persona MOTD, online and max players), recorded as a write with `status` `legacy_status_response` and the same `variant`/`visit` as a status response. The bare `FE` ping of Beta 1.8 is not recognized. The catch-all reroutes `FE 01` (with nothing or `FA` after it) from any port; `FE 01 00` is a 254-byte Handshake prefix and stays modern.
