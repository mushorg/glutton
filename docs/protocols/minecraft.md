# `minecraft` decoded data

Transport: TCP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `path`, `status`, `protocol_version`, `port`, `next_state`, `username`, `uuid`, `state`, `message`, `password`, `channel`, `brand`, `locale`, `packs`, `count`, `variant`, `visit`, `truncated`, `payload`

Minecraft Java. `command` is `handshake` (`path` is the server address the client typed), `status_request`, `ping`, `login_start` (`username`, plus `uuid` when the client sent one: 1.20.2+ always, 1.19.3–1.20.1 when its has-UUID flag is set), `malformed` (partial or oversize frame, `truncated`) or `unknown`. Writes set `status` `status_response`, `pong`, or the login Disconnect reason: `incompatible` / `outdated_client` (login Handshake protocol is not the persona's; below 754 is `outdated_client`), `transfers_disabled` (next state 3), or `not_whitelisted` (Login Start with the persona's protocol on a persona that is not open). On the open persona Login Start gets `login_success` instead; see [Open persona sessions](#open-persona-sessions).

Replies mimic a vanilla 1.21.x dedicated server in offline mode with a whitelist. The version, MOTD and players come from a persona picked per source visit, and the status JSON advertises the persona's version whatever protocol the client sends (see `recall.enabled` in [configuration](../configuration.md)). A first visit gets `default`, `{"description":"A Minecraft Server","players":{"max":20,"online":0},"version":{"name":"1.21.4","protocol":769}}`; a source returning after `recall.visit_gap` gets the next of `smp` (1.21.8 / 772, `Friends SMP`, 2 of 10 online) and `survival` (1.21.1 / 767, `survival server - whitelist only`, 1 of 20 online), whose `players.sample` lists the online names with their offline-mode UUIDs. The persona's protocol also gates login: a client on that protocol reaches `not_whitelisted` (`default`, `survival`) or logs in (`smp`), others get `incompatible`/`outdated_client` naming the persona's version. The `status_response`, `legacy_status_response` and login Disconnect writes carry `variant` (the persona) and `visit` (the source's visit number). Disconnects carry translatable components (`{"translate":"multiplayer.disconnect.…"}`). Version and transfer rejections are sent right after the Handshake, as vanilla does, so they come before any Login Start. The handler then waits up to 500 ms for a Login Start already in flight and records it (`username`) without answering. A second Status Request closes the session. No encryption, compression or Mojang authentication.

The rule routes tcp/25565 here. On any other port the `tcp` catch-all peeks the first segment and reroutes a complete Handshake (length prefix 6–266, packet ID `0x00`, address of 255 bytes or less, next state 1–3, fields ending at the declared length) to this handler, so server-list scanners on high ports (e.g. matscan) show up as `minecraft`.

**Legacy ping.** A pre-1.7 server list ping (`FE 01`, optionally followed by the `FA MC|PingHost` plugin message; nmap sends it) is read as one frame with `command` `legacy_ping` and answered with a 1.4+ kick packet (`0xFF`, UTF-16BE `§1`, protocol 127, the persona's version name, MOTD, online and max players), recorded as a write with `status` `legacy_status_response` and the same `variant`/`visit` as a status response. The bare `FE` ping of Beta 1.8 is not recognized. The catch-all reroutes `FE 01` (with nothing or `FA` after it) from any port; `FE 01 00` is a 254-byte Handshake prefix and stays modern.

## Open persona sessions

The `smp` persona (a source's second visit) is an offline-mode Fabric server with an auth mod: it accepts any username so the session continues into the game. Only protocol 772 (1.21.7/1.21.8) is implemented. Every frame after Login Start carries `state` (`login`, `configuration`, `play`); read frames carry `command`, Mojang's packet name for that state (`login_acknowledged`, `client_information`, `custom_payload`, `select_known_packs`, `finish_configuration`, `chat_command`, `chat_command_signed`, `chat`, `move_player_pos`, …, or `unknown`).

| Stage | Honeypot writes (`status`) | Client reads recorded |
| --- | --- | --- |
| login | `login_success` (offline UUID of the name, no properties; tagged `variant`/`visit`) | `login_acknowledged` |
| configuration | `brand` (`fabric`), `feature_flags` (`minecraft:vanilla`), `known_packs` (`minecraft:core` 1.21.8); after the client's Known Packs, `registry_data` (21 Registry Data packets with entry data left to the client's core pack; the frame has `count` 21 and no `payload`, since the bytes are the same every session) and `finish_configuration` | `custom_payload` (`channel`, `brand` on `minecraft:brand`), `client_information` (`locale`), `select_known_packs` (`packs` as `namespace:id@version`), `finish_configuration` |
| play | `login`, `player_position`, `spawn_position`, `wait_for_chunks` (Game Event 13), then `auth_prompt` (system chat `Please register with /register <password> <password>`) | everything, by name |

In play, `chat_command` and `chat_command_signed` set `message` (the command without `/`) and `chat` sets `message`. `register`/`reg` and `login`/`l`/`log` commands set `password` to their first argument (recorded in plaintext; these are guesses). The first one gets `auth_ok` (`Successfully registered! You are now logged in.` or `Successfully logged in.`); chat or other commands before that get `auth_prompt` (`You need to log in first: /login <password>`). `keep_alive` writes go out every 15 s in configuration and play. Packets a client sends every tick (`client_tick_end`, `move_player_*`, `player_input`, `keep_alive`, `chunk_batch_received`, `accept_teleportation`, `chat_ack`, `swing`) fold into one frame with `count` while only such frames follow it. A session ends when the client leaves, after 2 minutes, after 4096 packets, or idle past `conn_timeout`; at most 256 frames are kept (the last one gets `truncated`).

Not emulated: chunks (a vanilla client stays on the loading screen for up to 30 s, then spawns in an empty world), Update Tags, other players, commands. The world (seed, spawn, entity ID) is picked once per process.
