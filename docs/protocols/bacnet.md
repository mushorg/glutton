# `bacnet` decoded data

Transport: UDP. Shared encodings and frame fields are described in [Logging and producers](../logging.md#decoded-data).

**`decoded`:** Array of per-direction frames: `direction`, `command`, `bvlc_function`, `invoke_id`, `path`, `property`, `array_index`, `low_limit`, `high_limit`, `password`, `status`, `payload`, `truncated`

BACnet/IP (udp/47808). `bvlc_function` is the BVLC function (`ORIGINAL_UNICAST_NPDU`, `ORIGINAL_BROADCAST_NPDU`, `FORWARDED_NPDU`, `READ_BDT`, …). `command` is the APDU service (`READ_PROPERTY`, `WHO_IS`, `READ_PROPERTY_MULTIPLE`, `WRITE_PROPERTY`, `REINITIALIZE_DEVICE`, …), `NETWORK_MESSAGE_0xNN` for network-layer messages, the BVLC function for BVLL-only datagrams, or `UNKNOWN` (short datagram or BVLC type not `0x81`). `invoke_id` is set on confirmed requests. `path` is the object identifier `<type>:<instance>` (`device:4194303` is the wildcard instance scanners use) and `property` the property name (`object-identifier`, `vendor-name`, …) or number. `low_limit`/`high_limit` are the Who-Is range. `password` is the plaintext password of DeviceCommunicationControl/ReinitializeDevice.

The handler answers as one building controller with a stable per-sensor identity (device instance, vendor, model, firmware, object name and location derived from the sensor address): Who-Is (unranged or with the instance in range) gets `I_AM`; ReadProperty on the device object gets `READ_PROPERTY_ACK` for the identity properties (object-identifier/name/type, description, location, model-name, vendor-name/identifier, firmware-revision, application-software-version, system-status, protocol-version/revision, max-apdu-length-accepted, segmentation-supported) and `ERROR:property/unknown-property` otherwise; other objects or another device instance get `ERROR:object/unknown-object`; writes get `ERROR:property/write-access-denied`, device control `ERROR:security/password-failure`, other confirmed services `REJECT`. Read-BDT/Register-Foreign-Device/Read-FDT get a `BVLC_RESULT_NAK_0x00NN`. Replies always go to the datagram source. Datagrams over 1536 bytes are capped with `truncated` and not answered.
